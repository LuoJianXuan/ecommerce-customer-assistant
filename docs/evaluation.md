## 指标与限制

- Recall@k（前 k 条参考块覆盖率）：对每题计算前 k 条命中的参考知识块数量 / 该题参考知识块数量，再逐题取平均。它不是“命中任意一块即记成功”的题级命中率。
- MRR（平均倒数排名）：第一条参考知识在返回结果中的排名倒数，未命中记 0，再取平均。JSON 保留 0—1 小数；人读报告统一用百分数。
- 四策略均在同一 73 题上比较。混合加重排为 Recall@5 98.17%、Recall@10 98.17%、MRR 96.92%。这组结果并不表示重排在每个指标上都优于所有单路召回。
- 检索策略比较使用查询改写；生成段与证据闸诊断使用原始问题。配置开关和实际评估路径必须一起看。
- 生成段直接使用召回证据与应答提示，和证据闸诊断分开执行；不是 `/api/agent/chat` 全工作流端到端测试。
- 73 条有据题的裁判有效，编造检出 0；其中 6 条语义拒答。27 条库外题均拒答。模型零检出不是人工确认全部正确，也没有生产零幻觉的含义。
- C19 首次裁判 JSON（结构化数据格式）无法解析，保持回答和证据不变，仅重试裁判；前后记录和重试原文均已保留。无法解析的裁判不计为忠实通过。
- 当前阈值 0.20 放行 55/73 条有据题、拦截 27/27 条库外题；误拦率为 24.66%。同集扫描候选阈值 0.05 没有自动应用，也不是独立测试集上的收益。

## 数据与配置快照

固定目录包含修订题集、逐题排名、证据、生成答案、裁判、阈值样本和运行配置。

- 原运行知识表有 39 条 active（可检索）及 250 条 quarantined（已隔离）材料。公开 `knowledge_snapshot.json` 只保留 39 条有效知识；不会上传隔离材料原文。
- `record_manifest.json` 保存原始运行清单与哈希；其完整知识快照哈希对应未公开原件。`manifest.json` 保存筛选后的公开快照哈希，二者含义不同。
- `run_config.json` 泛化了本机根路径、移除了工作区文件状态清单，保留当次源码哈希和脏工作区标记。源码文件哈希描述被评估代码，不能单凭原 Git 提交号重建全部未提交改动。
- `runner_record.py` 是当次原始运行脚本的留档，哈希与原记录一致；新运行使用 `evals/run_audit.py`，避免导出全部私有知识或覆盖冻结结果。
- `checksums.json` 核验公开文件完整性，不包含自身。外部模型别名、随机回答、软件和底层计算变化都可能影响新一轮结果，不能保证逐字或逐位一致。

## 离线核验

只需要 Python 标准库：

```powershell
python evals/verify_release.py
```

该命令核对哈希、标签分母、39 条有效知识、292 条四策略检索记录、100 条生成记录、证据闸计数及分类器固定指标，不访问服务或发送请求。

## 完整重跑

先按[运行指南](setup.md)初始化独立数据库、向量库和 39 条公开知识，配置模型接口。该步骤会向配置的模型服务发送演示题目、知识证据及回答，并消耗接口额度；本次仅做启动验收，没有重跑该 100 题评估。

```powershell
# 输出目录必须尚不存在；每一轮使用新名称
.\.venv\Scripts\python.exe evals/run_audit.py --output tmp/rag-run-001
# 仅在裁判出现无法解析记录时执行，不重新生成答案
.\.venv\Scripts\python.exe evals/retry_judges.py --run tmp/rag-run-001
```

新审计入口默认读取固定的 100 题，生成不受旧工作台的 `EVAL_GEN_LIMIT` 限制；新结果写入 `tmp/`。它没有更改运行阈值，也不会自动成为新的公开指标。
